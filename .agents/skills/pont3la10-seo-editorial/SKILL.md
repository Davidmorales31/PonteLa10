# Pont3la10 SEO Editorial

Apply after research and before submitting a draft. SEO improves discovery and
clarity; it never overrides accuracy, public value, or the human review gate.

1. Start from the actual question and search intent found during research. Use
   one primary query and a small set of related queries only when supported by
   the evidence. Never claim search volume or rising demand unless the research
   source provides that signal and observation time.
2. Write a specific, natural title and a distinct summary/meta description that
   accurately represent the article. Include the main entity or query only when
   it reads naturally. No repeated boilerplate keywords, misleading curiosity
   gaps, false urgency, or title/body mismatch.
3. Make the story useful beyond a search phrase: verified development first,
   context, chronology, consequences, and clear attribution of uncertainty.
   Expand only when sources support meaningful detail; never add filler for a
   word-count target.
4. Suggest public taxonomy from the supplied active catalog. Reuse existing
   topics; propose a new public topic only when it is specific, durable, and
   materially improves discovery. Never create categories or internal labels.
5. Relate only to published stories supplied by the API and only when the link
   helps the reader. Do not invent URLs or link drafts as if they were public.
6. Keep source citations as structured source records mapped to claims, outside
   the article body. Do not invent author, publication date, image, credentials,
   or structured-data facts. Respect the existing article/schema contract.
7. Before delivery, check title/description length and uniqueness against the
   current batch; verify entity spelling, dates, canonical source links, image
   attribution if present, and consistency between title, summary, body, and
   primary query. Flag unresolved or sensitive claims for the human editor.

Return only fields required by the current Codex/DeepSeek contract. SEO terms,
taxonomy, and relationships are proposals; server validation and Juan's review
remain authoritative. Never approve, schedule, or publish.
