  evitando repetir redacción/portada de piezas ya registradas.

- **Primer hito HU-ED-13:** el worker manda un latido independiente cada minuto,
  incluso en reposo; la ausencia de la migración no detiene el worker actual.
  La nueva API privada firmada `/api/internal/codex/health` devuelve estado
  activo/desconectado/desconocido, conteos y edad de cola/evidencia, corridas
  Codex, atraso de programadas y última ejecución del Cron si está disponible.
  No devuelve el mensaje crudo de Cron ni reintenta o altera datos. Se añadió
  `pont3la10-operational-monitor`, limitada a consultas de solo lectura, y el
  cliente permite invocar la ruta `salud`. Los latidos antiguos se purgan después
  de 30 días. Revisión
  estática encontró/corrigió vencimiento de `stopping`, Cron sin job configurado
  y retención. La tabla no permite escritura directa a clientes; la única RPC de
  latido exige `auth.uid`, worker exclusivo y permiso, fija las marcas de tiempo
  en la base de datos y concede ejecución solo a `authenticated`. Re-revisión
  estática final sin hallazgos; no sustituye pruebas PostgreSQL.
- **Reanudación añadida:** `scripts/codex-editorial-checkpoint.mjs` guarda
  expedientes, borradores, portada, media, payload de propuesta y recibo por
  corrida/categoría/huella. Guarda portada por contenido SHA-256, reutiliza
  etapas idénticas, permite enumerar candidatos de una corrida y exporta la
  etapa exacta a archivo ignorado sin imprimir el artículo. Un replay preexistente
  solo se reutiliza si coincide exactamente; no pisa archivos diferentes.
  Restringe el JSON con base64 al directorio del candidato. Preparar ese payload
  también es idempotente: reutiliza el archivo solo si coincide exactamente y
  falla cerrado si hay colisión (2 pruebas focales pasan). Las Skills diaria y
  de seis horas permiten retomar solo entregas idempotentes ya preparadas (un
  intento por chequeo), sin regeneración ni publicación.
